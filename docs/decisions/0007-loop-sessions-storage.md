# 0007. 루프·세션·저장 정책

- 상태: 초안 (2026-10-02)
- SSOT: `loop/policy.json`, `loop/schema/*`, 원칙 `specs/principles.json`(L1–L8, A1, A9)
- 실행 가능한 전제: P-0007-a

## 결정
- **저장**: 상태(백로그·반복 기록·원장·정책·스키마)는 커밋한다. 원본 산출물(명령 출력·로그·프로파일)은 `loop/.runs/`에 로컬로 두고(gitignore, 보존 30일) 원장은 요약 값과 sha256만 갖는다. 비밀 패턴은 기록을 거부한다.
- **세션**: 세션 하나 = 작업 하나 = 반복 하나. worker·verifier·watch는 새 컨텍스트로 시작하고 시작 루틴(git 상태 → `make orient` → `make verify`)과 반복 기록(summary·next)으로 잇는다. bootstrap(이 정책을 만든 세션)만 예외.
- **시작 조건(readiness)**: 자율 루프(worker·watch)는 게이트·의존성·기계 판정 가능한 완료 조건·명세 안정(14일 내 명세 변경 ≤10커밋)을 만족할 때만 시작한다. 0→1은 사람 주도(design).
- **2행정**: 발산 펄스(조사·후보)는 예산 안에서 짧게, 결과는 원장·백로그로 압축. 수렴(게이트 사다리, 0토큰부터, 실패 시 중단)이 기본.

## 근거
- 실증 연구: 루프 설정은 커밋되지만 상태 파일은 거의 커밋되지 않는 공백(arXiv 2608.21884).
- 장기 실행 하네스: 진행 파일·기능 목록·git·고정 시작 루틴으로 세션 간 연속성(Anthropic).
- 긴 컨텍스트는 성능을 떨어뜨린다(Chroma context rot). 이 결정을 만든 세션 자체가 매우 길었다.
- 외부 피드백 없는 자기 교정은 효과 없음(ICLR 2024), 검증기가 있을 때만 반복이 성능으로 바뀜(Large Language Monkeys).
- 서브에이전트 3개 조사 펄스 ≈ 46만 토큰(이 세션), 결정적 게이트는 0토큰.

## 재검토 조건
- 원장·반복 기록이 커져 리뷰가 어려워질 때(압축·아카이브 정책), 세션 id를 자동으로 얻을 수 있게 될 때.
