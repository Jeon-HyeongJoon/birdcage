# 0011. 미리보기: 받기 전에 보고, 듣고, 고른다

- 상태: 초안 (2026-10-03)
- 실행 가능한 전제: P-0011-a, P-0011-b, P-0011-c (`docs/decisions/premises.json`)

## 배경
사용자 정의(2026-10-03): Birdcage는 다운로더가 아니라 검색·찾아보기 도구이고, 사용자는 미리보기에서 가장 많은 정보를 얻는다.
목적은 미리보기 + 오디오 그래프 + 타임라인으로 원하는 부분을 골라 Premiere에 넣는 것. 썸네일 한 장과 정적 구간 막대는 활용도가 낮았다.

## 실측 (M1 Pro, 10분 35초 YouTube aqz-KE-bpKQ, 2026-10-03)
| 방식 | 비용 | 판단 |
|---|---|---|
| 서버에서 바로 프레임 추출(ffmpeg 범위 요청) | 프레임당 149–181ms, 영상을 받지 않음 | 스토리보드가 없을 때 첫 화면 |
| YouTube 스토리보드(yt-dlp sb0–sb3) | sb2(80×45, 10×10) 2장 82KB 0.6s, sb1 6장 254KB, 쿠키 불필요 | 필름스트립·스크럽 미리보기. 19초 영상엔 없음 |
| 오디오만 받기 + 파형 피크 | 2.2s(9.8MB) + 0.9s | 오디오 그래프를 먼저 |
| 360p 미리보기(yt-dlp 분할) | H.264 28MB 4.2s, VP9 33MB 4.9s | 재생·스크럽 |
| 단일 요청으로 통째로 받기(curl) | 4.3MB에 318s(속도 제한) | 쓰지 않는다(yt-dlp 분할만) |
| 검색 ytsearch10(flat) | 1.6–1.8s, 제목·길이·썸네일·조회수 | T-026 |

## 결정
- 단계적 미리보기: ① 스토리보드(조회 결과에 이미 있음) → ② 오디오 먼저 받아 파형 → ③ 360p H.264 비디오 전용을 받아 받아 둔 오디오와 로컬 결합(복사, faststart) → 재생.
  플랫폼 스토리보드가 없으면(짧은 YouTube·TikTok·Instagram) ③의 미리보기에서 같은 형식(160×90, 10×10)의 시트를 만든다.
  서버 프레임 추출(149–181ms/장)은 실측으로 가능함을 확인했지만, 스토리보드가 없는 출처는 대부분 짧아 ③이 금방 끝나므로 1차에서는 넣지 않았다.
  오디오 전용 포맷이 없는 출처(직접 링크)는 360p 이하 하나만 받아 파형과 영상에 같이 쓴다.
  같은 오디오를 두 번 받지 않는다. 패널은 CEP가 재생을 문서로 보장하는 MP4(H.264+AAC)만 재생한다.
- 캐시는 메모리가 아니라 디스크(Helper 데이터 폴더 `preview/`), 영상별 폴더, 전체 2GB 상한에서 오래 안 쓴 것부터 지운다. 같은 영상을 다시 보면 재사용.
- 파형 디자인(사용자 지시 2026-10-03): 막대그래프가 아닌 **가는 선그래프 하나**로 높낮이만 보인다(채움·대칭·격자 없음).
  피크는 dBFS로 바꿔(−48dB → 0, 0dB → 1) 조용한 구간도 보이게 한다. 데이터는 Helper가 구간별 선형 피크(0–255)로 보내고 표시는 패널이 정한다.
- 타임라인: 필름스트립 + 선 파형 + In/Out 핸들 + 재생헤드, 확대/축소(10분을 400px에 펴면 1px ≈ 1.5s라 정밀 선택에 필요), 시간 입력과 동기화.
  단축키는 Premiere와 같게(Space·I·O·←/→), CEP `registerKeyEventsInterest`로 호스트에 넘어가지 않게 한다(실기 확인 T-023).
- 작업 화면과 다운로드 관리는 분리한다(T-030). 기본 Birdcage 패널은 현재 링크의 미리보기·세부정보·받기 옵션만 보여 주고 받기 버튼을 옵션 바로 다음에 둔다.
  요청 뒤 진행·완료 목록은 별도 `Birdcage 다운로드` CEP 패널에서 본다. 두 패널은 Helper를 중복 실행하지 않고 CEP 이벤트로 상태·명령만 공유한다.
  Helper는 다운로드 최대 2개(같은 호스트는 1개), 링크 조회 최대 2개를 이미 병렬 처리하므로 사용자는 받기가 도는 동안 다른 링크를 조회·조정·요청할 수 있다.

## 재검토 조건
- Premiere 실기에서 `<video>` 재생·탐색이 느리거나 안 되면(T-023) 프레임 시퀀스(JPEG) + `<audio>` 방식으로 바꾼다.
- YouTube가 스토리보드 형식을 바꾸면 서버 프레임 추출로 대체(이미 대체 경로 있음).
- 받는 도중 재생(점진 재생)이 필요할 만큼 대기 시간이 길다는 사용 기록이 쌓이면 조각 MP4 스트리밍을 검토한다.
