# 0012. 탐색 목록: 미리보기 옆에서 다음 레퍼런스를 고른다 (실험)

- 상태: 초안·실험 (2026-10-04, 브랜치 `feat/recommendations`, T-036)
- 실행 가능한 전제: P-0012-a, P-0012-b, P-0012-c (`docs/decisions/premises.json`)
- 되돌리기: 적합성이 낮으면 브랜치를 병합하지 않는다. 일부 출처만 쓸모 있으면 그 출처만 남긴다.

## 배경
사용자 정의(2026-10-03): Birdcage는 다운로더가 아니라 검색·찾아보기 도구다. 추천 같은 탐색 기능은 나중에 넣기로 했다.
Premiere에서 패널을 최대화하면 미리보기 오른쪽이 비어 남는다(사용자 QA 2026-10-04). 사용자 제안: 넓은 화면은 오른쪽 사이드바, 좁은 화면은 유튜브처럼 미리보기·받기 아래에 추천 목록을 둔다.

## 실측 (M1 Pro, 로그인 없음, hl=ko·gl=KR, 2026-10-04)
| 출처 | 방법 | 시간 | 항목 | 판단 |
|---|---|---|---|---|
| 유튜브 '다음 동영상' | 시청 페이지 HTML(1.2MB)의 `ytInitialData` | 중앙값 0.89s(0.64–1.23s) | 시드 10개 중 9개가 20–26개, 필드(제목·채널·길이·썸네일·조회수) 100% | 1차 출처 |
| 〃 더 보기 | `/youtubei/v1/next` continuation | +1s | +20개 안팎 | 나중(필요가 확인되면) |
| 같은 채널 | yt-dlp `--flat-playlist <channel>/videos` | 0.81–1.09s | 30개 | 대체 1 |
| 비슷한 제목 | yt-dlp `ytsearch30:<제목 핵심어>` | 2.14–2.15s | 29–30개 | 대체 2 |
| 유튜브 믹스(RD) | yt-dlp | — | 로그인 없이는 빈 목록 | 쓰지 않는다 |

미리보기와 동시에 받을 때(넓은 패널) — `TestMeasurePreviewWithRelated`, 영상 3개(10:35·5:59·4:41), 혼자/동시 교대, 매번 미리보기 캐시 삭제, 2회:
| 단계(3개 합) | 혼자 | 목록 동시 | 차이 |
|---|---|---|---|
| 파형 표시 | 5840 / 5826ms | 5937 / 5963ms | +1.7% / +2.4% (영상당 약 +45ms, 영상별 −125…+231ms로 부호가 섞임) |
| 재생 준비 | 13981 / 13647ms | 13617 / 13653ms | −2.6% / +0.0% |
| 목록 도착 | — | 0.74–1.08s | 미리보기 준비(3.7–5.7s)보다 먼저 |

파형 단계의 +2% 안팎은 같은 조건 3회 재현(W4) 전이고 영상별 차이보다 작아 회귀로 보지 않는다. 다시 재면 `BIRDCAGE_MEASURE=1 go test -run TestMeasurePreviewWithRelated ./cmd/birdcage-helper/`.

시드 1개(YbJOTdZBX1g)는 시청 페이지에 `secondaryResults`가 없다(재생 제한 영상). 이때 Helper는 같은 채널 → 제목 검색으로 넘어간다.

공식 API가 없다: YouTube Data API `relatedToVideoId`는 2023-08-07에 폐지되었다. 시청 페이지 형식은 바뀐다:
2025년 항목이 `compactVideoRenderer`에서 `lockupViewModel`로 바뀌어 NewPipe·FreeTube·Invidious의 관련 영상이 깨졌다(NewPipeExtractor PR #1320).
그래서 두 형식을 다 읽고, 모르는 형식이면 다음 출처로 넘어가며, 실제로 채운 출처를 패널에 그대로 보여 준다.

## 결정
- Helper `related` 패키지: `related.fetch {probeId, source}` → `related.list {requested, source, items}`. 출처는 정직하게 이름을 붙인다:
  `추천`(유튜브 '다음 동영상' 그대로), `같은 채널`, `비슷한 제목`(제목 검색). 대체 순서 youtube → channel → search, 출처·영상별 30분 캐시(64개).
  지금 영상, 중복, 재생목록·믹스, 생방송(받을 수 없음)은 뺀다. 유튜브 링크만 지원한다(TikTok은 범위 밖).
- 시청 페이지 요청은 로그인 없는 한국어 브라우저처럼 한다(`hl=ko&gl=KR`, `Accept-Language: ko-KR`, EU 동의 화면을 건너뛰는 `SOCS=CAI` 쿠키 — yt-dlp `_initialize_consent`와 같은 값).
- 패널: 넓은 패널(≥960px)은 오른쪽 340px 사이드바(목록만 따로 스크롤, 미리보기는 화면에 남는다), 좁은 패널은 받기 옵션 아래.
  960px는 사이드바를 빼도 미리보기가 600px 이상 남는 폭이다. 감싸는 요소 없이 `.app`만 넓을 때 줄바꿈 flex로 바꿔 목록이 없는 화면은 구조·배치가 그대로다.
  카드 없이 행(썸네일 128×72, 길이 배지, 제목 두 줄, 채널, 조회수·게시 시점, 받은 영상은 `✓ 받음`)과 구분선만 쓴다.
- 비용: 목록은 보이거나 미리보기 준비가 끝난 뒤에 받는다(미리보기 360p 받기와 대역폭을 다투지 않게). 썸네일은 336×188 jpg(행당 약 20KB, 목록 전체 약 0.5MB)로
  레티나에서 선명하게 보이는 가장 작은 크기이고, CEP 10(Chromium 74)에는 `loading=lazy`가 없어 지연 로딩은 넣지 않았다(목록 하나가 0.5MB라 이득이 작다).
- 항목을 누르면 미리보기가 그 영상으로 바뀌고(조회 중엔 아는 썸네일·제목을 먼저 보여 준다), 지금 링크는 기록(최대 20개)에 남는다.
  `←`(이전 영상)은 구간·화질·오디오만·자막·목록 탭을 되살린다. 15분 안이면 Helper의 조회를 그대로 쓰고(미리보기는 디스크 캐시라 바로 뜬다),
  그 뒤거나 Helper가 조회를 이미 버렸으면(20분·16개 한도) 다시 조회하고 고른 값을 이어 쓴다.

## 적합성 판정 (병합 조건)
1. 자동(L1·L3): 녹화한 실제 응답 계약 테스트(P-0012-a), 실제 YouTube에서 시드 90% 이상이 10개 이상·첫 목록 중앙값 1.5s 이하(P-0012-b), 미리보기 단계 시간 회귀 없음.
2. 사용 기록: Helper 성능 로그에 출처별 목록(`related.list`), 목록에서 연 영상(`related.open`), 그 영상의 받기(`related.download`)가 남는다.
   `node scripts/related-report.mjs`가 출처별 열기/목록, 받기/열기 비율을 보여 준다.
3. 사람(L5): 실제 레퍼런스 찾기에 쓸모 있는지. 쓸모없으면 브랜치를 버리고, 한 출처만 쓸모 있으면 나머지를 뺀다.

## 하지 않은 것
- 무한 스크롤(continuation): 시청 페이지가 20–26개를 주고, 더 필요한지는 사용 기록으로 판단한다.
- 자체 추천 알고리즘(태그·임베딩): 근거(사용 기록) 없이 만들지 않는다. 같은 채널·제목 검색이 그 자리를 먼저 채운다.
- 설정 토글: 실험 브랜치를 병합하지 않는 것이 되돌리기다. 병합 뒤에 끄고 싶다는 요구가 생기면 넣는다.
