# 0013. 유튜브 검색: 상단 검색창 → 탐색 목록 '검색' 탭 (실험, TikTok 검색 제외)

- 상태: 초안·실험 (2026-10-04, 브랜치 `feat/search` — `feat/recommendations` 위, T-026)
- 실행 가능한 전제: P-0013-a, P-0013-b, P-0013-c (`docs/decisions/premises.json`)
- 되돌리기: 0012와 함께 판단한다. 검색만 쓸모 있으면 이 브랜치의 검색 커밋만 남기고 추천 목록을 뺀다.

## 배경
사용자 제안(2026-10-04): 유튜브/TikTok 검색을 스위치로 고르고, 검색한 영상을 누르면 링크로 들어가 기존 흐름(미리보기 → 구간 → 받기)과 이어지게 한다.
제품 정의(2026-10-03): Birdcage는 검색·찾아보기 도구다(0011). 탐색 목록(0012)이 같은 목록·열기·[←] 흐름을 이미 갖고 있다.

## 실측 (M1 Pro, 로그인 없음, hl=ko·gl=KR, 2026-10-04)
| 대상 | 방법 | 결과 |
|---|---|---|
| 유튜브 검색 | 결과 페이지 HTML `ytInitialData`(1.3–1.6MB) | 검색어 5개 4회: 첫 페이지 중앙값 0.91–1.37s, 영상 12–20개(필드 100%) + 쇼츠 묶음 20–25개 |
| 〃 더 보기 | 페이지가 준 continuation → `/youtubei/v1/search` | 0.73–1.48s, 새 영상 +4–13개 |
| 〃 대체 | yt-dlp `ytsearch20`(flat) | 1.71–2.16s, 20개 |
| TikTok 검색 | yt-dlp | 검색 추출기가 없다(`tiktok:tag`도 CURRENTLY BROKEN, 2026.08.19) |
| 〃 | `tiktok.com/search?q=` HTML | 0.5s, 결과 0개(브라우저에서 따로 그린다) |
| 〃 | `/api/search/general/full/` | 서명 없이 빈 응답(0바이트) |
| TikTok 계정 영상 | yt-dlp `tiktok:user` flat | 2s, 10개(길이 포함) — 동작 |

유튜브는 같은 검색어에도 요청마다 쇼츠 묶음 비중이 달라 첫 페이지 영상 수가 12–20개로 바뀐다(저장한 페이지에서는 파서가 영상을 모두 읽음을 확인).
처음 완료 기준(15개·더 보기 +10개)은 표본 5개로 정한 값이라, 4회 실측 하한에 맞춰 10개·+3개로 고쳤다(T-026 수용 기준에 기록).

## 결정
- 유튜브 검색만 넣는다. TikTok 검색은 로그인 없이 결과를 얻을 길이 없고, 되게 하려면 TikTok의 봇 차단 서명을 우회해야 해(숨긴 브라우저) 무겁고 자주 깨지며 바람직하지 않다.
  한쪽이 동작하지 않는 플랫폼 스위치는 넣지 않는다. TikTok 링크 붙여넣기는 그대로다. TikTok '같은 계정' 목록은 동작이 확인되어 다음 후보로 남긴다.
- Helper: 결과 페이지를 직접 읽는다(yt-dlp보다 약 0.9s 빠름). 영상(videoRenderer·lockupViewModel)만 모으고 쇼츠 묶음·재생목록·생방송·예정 영상은 뺀다.
  더 보기는 페이지 단위 continuation(섹션 목록의 마지막 continuationItemRenderer — 필터 칩의 토큰을 쓰면 빈 결과가 온다, 실측)과 첫 페이지의 클라이언트 버전·방문자 값으로 요청한다.
  결과 페이지 형식이 깨지면 첫 페이지만 yt-dlp `ytsearch30`으로 대체한다(더 보기 없음). 검색어별 30분 캐시(32개), 검색어는 공백 정리·100자 제한.
  `search.fetch {query, page}` → `search.list {query, page, items, more}`. 페이지는 순서대로만 받는다.
- 패널: 머리줄에 `유튜브 검색` 칸(Enter). 링크 칸에 링크가 아닌 글자를 넣고 Enter를 눌러도 검색한다. 입력 중 자동 검색은 하지 않는다(한 번에 약 1s·1.4MB).
  결과는 탐색 목록의 `검색` 탭에 나와 미리보기를 유지한 채 고른다(넓으면 사이드바, 좁으면 아래). 열린 영상이 없으면 목록이 본문 폭을 쓰고 넓은 패널에서 3–4열로 놓는다.
  검색 결과는 영상을 열거나 [←]로 돌아가도 남고, 추천 탭과 오갈 수 있다. 검색 탭을 보는 동안에는 추천 목록을 받지 않는다(필요할 때만 받는다).
- 적합성 기록: 검색 페이지(`search.list`), 검색에서 연 영상(`related.open via=search:youtube`), 그 영상의 받기를 성능 로그에 남기고 `scripts/related-report.mjs`가 함께 보여 준다.

## 하지 않은 것
- 정렬·기간·길이 필터: 사용 기록으로 필요가 보이면 결과 페이지의 `sp` 값으로 넣는다.
- 쇼츠 검색: 세로 영상이 필요하면 TikTok 대안으로 검토한다(결과 페이지에 쇼츠 묶음이 20–25개 있다).
